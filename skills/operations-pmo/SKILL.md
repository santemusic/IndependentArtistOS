# Operations / PMO

## Mission
Convert approved artist goals into reliable execution across every Agency.

## 1. Project creation
For every project capture: Project ID, Goal ID, objective, measurable outcome, scope, exclusions, accountable Agency CEO, project manager, start date, target date, budget constraint, workstreams, milestones, dependencies, risks, approval gates and success metrics.

## 2. Work breakdown
Decompose each milestone until every task has one owner, a concrete deliverable and an objectively testable definition of done. Avoid microtasks that add administration without reducing ambiguity.

## 3. Task readiness gate
A task may move to READY only when objective, owner, required inputs, deliverable, deadline, dependencies, approval owner, definition of done and next handoff are known. Otherwise use NEEDS_INPUT.

## 4. Dependency management
Classify dependencies as finish-to-start, approval, asset/input, external-party or fixed-date. Identify the critical path. Any dependency capable of threatening a release, contractual deadline, show or campaign launch is actively surfaced.

## 5. Blocker protocol
A BLOCKED task records: blocker, blocker owner, action required, impact, escalation level and next review date. P0/P1 blockers are surfaced to Ops CEO and relevant Agency CEO; Artist-level decisions go through Chief of Staff/Artist CEO.

## 6. Operating cadence
Daily: P0/P1, today's deadlines, publishing, approvals, blockers.
Weekly: goals, releases, content, growth, data, finance/legal attention, dependencies and Artist decisions.
Monthly: portfolio, budget, catalog, audience, revenue, relationships and process health.
Quarterly: goals, release strategy, organization design, automation opportunities and obsolete process cleanup.

## 7. Meeting protocol
Meetings exist for decisions, coordination or high-bandwidth problem solving. Prepare decisions required in advance. Capture explicit decisions, action owners and deadlines. Do not create meetings when asynchronous work is sufficient.

## 8. Definition of done enforcement
DONE requires the deliverable to exist, QA to pass, approval to be recorded when required, final location/link to be known, dependencies to be updated and next handoff to be triggered.

## 9. SOP lifecycle
Observe repeated process → document current successful method → define trigger/inputs/steps/QA/output/escalation → test manually → version → automate only stable deterministic portions → review after failures or material process changes.

## 10. Status reporting
Use RAG status only with evidence. Report: outcome status, milestones, completed deliverables, next actions, blockers, risks, decisions required and forecast date. Never report activity volume as project success.
